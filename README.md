# OpenSchool Desktop

Неофициальный открытый клиент электронного дневника **«Моя школа»** (Госуслуги) для компьютера. Вход через ЕСИА, расписание, домашние задания и оценки в одном окне, с настраиваемым оформлением.

> **Это независимый проект.** Он не связан с Госуслугами, «Моей школой» и их разработчиками, не одобрен ими и ничего не обходит: приложение ходит в те же запросы, что и сайт, под вашей собственной сессией, и только читает данные.

Ядро (работа с API) вынесено в отдельный репозиторий [OpenSchool-Bridge](https://github.com/Xomel45/OpenSchool-Bridge), оно подключено сюда как git-подмодуль (`bridge/`). Позже на нём же будет сделано Android-приложение.

## Что умеет

- **Вход через ЕСИА** в отдельном окне. Логин и пароль приложение не видит и не хранит: сохраняются только cookie сессии, в системном хранилище секретов (Secret Service/KWallet на Linux, Диспетчер учётных данных на Windows).
- **Главная:** карточка ученика, последние 16 оценок с подробностями по наведению, расписание дня с листанием по дням, домашние задания внутри карточек уроков, информация о четверти.
- **Расписание:** неделя семью колонками, календарь для перехода к любой дате, всплывающая карточка урока.
- **Задания:** домашние задания по дням, по 4 дня на странице, отметки «сделано», фильтр «только невыполненные».
- **Оценки:** таблица по четвертям и за год, цветные оценки, средний балл, «н» и пропуски.
- **Оформление:** стили (Классический, Терминал, Рассвет), тема (системная, светлая, тёмная), акцентный цвет со своим выбором и пипеткой, фон (цвет, градиент, **картинка, GIF, видео**), плавные анимации.
- **Перенос настроек:** экспорт и импорт оформления вместе с фоном одним файлом `.cfg` (обычный ZIP-архив).

Чего пока нет: школьных событий и рейтинга (источника данных для них нет или он не найден), настоящих итоговых оценок за четверть и год (их ещё не существует в API до конца четверти; сейчас показаны средние), открытия вложений к заданиям. Подробности в разделе «Статус».

## Платформы и статус

| Платформа | Статус |
|---|---|
| Linux x86_64 | разрабатывается и проверяется (KDE Plasma, Wayland) |
| Windows 10+ x86_64 | сборка настроена в CI, **вручную не проверялась** |
| Windows 10+ x86 (32 бит) | сборка в CI «по возможности», не проверялась |
| Android | ещё не начат (будет на ядре OpenSchool-Bridge) |

Проект молодой. Интерфейс проверялся на вымышленных данных в настоящем WebKit и вручную на Linux. Если что-то сломалось у вас, откройте issue.

## Установка из исходников

Готовых сборок пока нет. Нужен [Rust](https://rustup.rs) (stable) и `tauri-cli`:

```bash
cargo install tauri-cli --version "^2" --locked
git clone --recurse-submodules https://github.com/Xomel45/OpenSchool-Desktop
cd OpenSchool-Desktop
```

Если забыли `--recurse-submodules`: `git submodule update --init`.

**Linux** (Debian/Ubuntu; в других дистрибутивах пакеты называются похоже):

```bash
sudo apt-get install -y libwebkit2gtk-4.1-dev libjavascriptcoregtk-4.1-dev libgtk-3-dev \
  libsoup-3.0-dev librsvg2-dev libxdo-dev libdbus-1-dev pkg-config
```

Для сохранения сессии нужна служба секретов (KWallet, GNOME Keyring или совместимая).

**Windows:** Visual Studio Build Tools (C++), [NASM](https://www.nasm.us) в `PATH` (нужен для криптобиблиотеки). Сборка `i686-pc-windows-msvc` для 32 бит: `rustup target add i686-pc-windows-msvc`.

Запуск и сборка:

```bash
cd src-tauri
cargo tauri dev            # запуск для разработки
cargo build --release      # релизный бинарник: src-tauri/target/release/
cargo test                 # тесты
```

## Устройство

```
OpenSchool-Desktop/
├─ bridge/      подмодуль OpenSchool-Bridge: клиент API на Rust
├─ src-tauri/   Tauri 2: окно, вход через ЕСИА, хранилище секретов,
│               фон и экспорт настроек, пипетка (KWin)
├─ ui/          интерфейс на чистых HTML/CSS/JS, без сборщика
├─ dev/         инструменты разработки (см. ниже)
└─ .github/     сборка в CI
```

Интерфейс получает все данные через команды Tauri (`src-tauri/src/commands.rs`). Содержимое `ui/` вшивается в приложение при сборке, окно входа ЕСИА не имеет доступа к командам приложения.

## Разработка без аккаунта Госуслуг

В `dev/` лежат инструменты, которые позволяют работать с интерфейсом без входа: страница с подменой бэкенда и вымышленными данными.

```bash
python3 dev/make-mock.py        # собирает dev/mock.html из ui/index.html (в git не хранится)
xdg-open dev/mock.html          # открыть в браузере
```

Флаги в адресе (`#...`) включают разные сценарии: `#mode=login` (экран входа), `#mode=fail` (ошибки сервера), `#sys=dark|light`, `#slow=1`, `#eye=none`, `#pick=cancel|err`, `#clip=fail`, `#imp=bad|cancel`, `#bg=none`.

Проверка в движке, который использует приложение на Linux (WebKitGTK), без показа окна (нужны PyGObject и WebKit2 4.1):

```bash
WEBKIT_DISABLE_COMPOSITING_MODE=1 WEBKIT_DISABLE_DMABUF_RENDERER=1 LIBGL_ALWAYS_SOFTWARE=1 \
  python3 dev/webkit-run.py dev/mock.html --shot out.png
```

Страница может сама записать результат проверки: см. docstring в `dev/webkit-run.py`. Воспроизведение видео этот режим проверить не может.

## Приватность и безопасность

- Пароль от Госуслуг приложение не получает: вход идёт на странице ЕСИА в отдельном окне, приложение забирает только cookie после успешного входа и проверяет их запросом к серверу.
- Cookie хранятся в системном хранилище секретов, не в файлах. «Выйти» удаляет их.
- Данные ученика приложение не отправляет никому, кроме серверов Госуслуг. Никакой аналитики и телеметрии нет.
- Отметки «ДЗ сделано» и настройки оформления хранятся локально на вашем компьютере. Файл `.cfg` содержит только оформление и фон, не оценки и не отметки.
- Фон, который вы выбираете, копируется в папку данных приложения и отдаётся окну локальным сервером на `127.0.0.1` с секретным путём, доступным только этому процессу и окну.
- Загруженный `.cfg` проверяется как недоверенный: читаются только два известных файла внутри, размер ограничен, формат фона из белого списка.
